Getting started with Claude Code

A short guide for people who work with customers, not code. Skim it once, set up the four things in Section 1, and start using it.

What is Claude Code? An AI assistant that runs in your Terminal. You point it at a folder on your Mac and it can read files, write drafts, search the web, and run tasks — all by typing in plain English.

Why CSMs & AEs care: drafting customer emails, summarizing call notes, prepping for QBRs, comparing org artifacts, and doing the kind of "research + write" work that eats your morning.

1 One-time setup (5 minutes)

Don't love the idea of Terminal? You don't have to use it. Claude Code also has a desktop app for Mac — same Claude, but it runs in its own window instead of inside Terminal. The way you talk to it is identical. The rest of this guide still applies; just substitute "open the desktop app and pick a folder" for the Terminal steps. If that's the route you want, see the "Skip Terminal entirely" section below for setup. Otherwise, keep reading — Terminal really is fine once you've used it three times.

You've already installed Claude Code. Three small things to do before your first run:

1a. Create a shortcut alias in your Terminal

An alias lets you launch Claude with a short word instead of a long command. We'll set up two: claude for normal use and yolo for when you want it to run without asking permission for every action.

Open Terminal (Cmd+Space, type "Terminal", hit Enter), then paste this in and press Enter:

echo '
# Claude Code aliases
alias claude="claude"
alias yolo="claude --dangerously-skip-permissions"
' >> ~/.zshrc && source ~/.zshrc

That appends two lines to your shell config and reloads it. From now on, anywhere in Terminal:

  • claude — normal mode. Claude asks before doing anything that touches your files or runs commands.
  • yolo — Claude does what it needs to without asking. Faster, but only use it on folders where you trust what you're doing.
About --dangerously-skip-permissions: the name is dramatic on purpose. Claude won't ask permission to read, write, or delete inside the folder you launched it from. Don't run yolo from your home folder (~) or anywhere with files you can't afford to lose. Run it from a project folder where the worst case is "I have to redo this work."
1b. Pick (or make) a folder for Claude to work in

Claude works best when you launch it from a single folder, and then keep it focused on that folder. Whatever's in there is what Claude reads, edits, and writes to.

Technically Claude can reach out to other folders on your Mac if you ask it to. But the smart move is to treat the folder you launch from as its workspace. If you want to work on a different customer or project, quit Claude and re-launch it from that other folder. New folder = new Claude session.

Suggestions:

  • One folder per customer (e.g. ~/Documents/CustomerName)
  • Or one general folder (e.g. ~/Documents/Claude) with subfolders inside, one per task

Drop relevant context in there — call notes, a Success Plan PDF, an email thread you exported, a CSV from Gainsight. Claude reads what's there.

1c. Open that folder in Terminal, then launch Claude

The trick most people don't know:

  1. Open Finder and navigate to the folder you want.
  2. Right-click the folder (or two-finger click on the trackpad).
  3. Choose Services → New Terminal at Folder.

If you don't see "New Terminal at Folder," turn it on once: System Settings → Keyboard → Keyboard Shortcuts → Services → Files and Folders, and check the box for "New Terminal at Folder."

A Terminal window opens already inside that folder. Now type:

claude

or for the no-permission-prompts version:

yolo

Claude starts up and waits for you to tell it what to do.

1d. Skip Terminal entirely — use the desktop app instead

If Terminal feels alien, use the Mac desktop app. Same Claude, same way of talking to it, just in its own window.

  1. Download from the link your installer email pointed you at, or check #claude-code-support on Slack for the current download link.
  2. Drag the app to Applications. Open it.
  3. The app asks you to pick a folder when it launches — same idea as Terminal. Pick the folder you want it to work in (e.g. your Weekly Updates folder).
  4. Type your prompt. Done.

Things that are different in the app

  • No aliases. Aliases are a Terminal thing — they don't exist in the app. But you can still get the equivalent of yolo by going to Settings → Permission mode → "Bypass permissions". (Same warning applies: only use it on folders where the worst case is "I have to redo this work.")
  • Switching folders happens through a folder picker in the app, not by opening a new Terminal window.
  • Everything else — prompts, slash commands, file dragging, the way Claude reads your folder — works identically.

The rest of this guide is written for Terminal because that's what most people end up using, but every prompt, every slash command, and every workflow below works exactly the same in the app. If a section says "in Terminal, type X," do the equivalent in the app's chat box.

2 Your first conversation

Once Claude is running, you just type. No special syntax. Examples that work on day one:

  • "What files are in this folder?"
  • "Read the call notes PDF and summarize the top 3 risks."
  • "Draft a follow-up email to the customer based on the notes from yesterday's call."
  • "Compare the Q1 and Q2 success plans and tell me what changed."

When you're done, type /exit or press Ctrl+C twice.

Tip: the more context you give upfront, the better the answer. "Draft a renewal email" is fine. "Draft a renewal email to the customer team — VP of Eng is the buyer, we're 60 days out, the main concern from last call was integration timeline" is much better.

3 A few things worth knowing

How do I stop Claude mid-task?

Press Esc once. It interrupts whatever it's doing and waits for new input. Press Ctrl+C twice to fully quit.

Can I drag a file into the conversation?

Yes. Drag a file from Finder into the Terminal window and the path drops in as text. You can also just say "look at the file called X" and Claude will find it in the folder.

For images (screenshots of dashboards, error messages, etc.), drag them in the same way — Claude can read them.

What does the slash / do?

Typing / at the start of a message opens a list of built-in commands. Useful ones:

CommandWhat it does
/helpLists everything available
/clearWipes conversation memory and starts fresh (use this between unrelated tasks)
/supportSalesforce-internal: diagnoses common install/sign-in issues, hands off to #claude-code-support if needed
/exitQuits Claude
What's the difference between claude and yolo again?

claude asks for permission before doing anything that affects your files or runs a command. Safer, slightly slower.

yolo skips those prompts. Faster for repetitive work, but you're trusting Claude not to delete or overwrite something you cared about. Rule of thumb: use claude when you're new or experimenting, yolo when you've used it enough to know what to expect.

Will Claude remember our last conversation?

Not by default. Each time you launch, it starts fresh — but it can read any files in the folder, so if you save your notes there, you've got persistent memory the easy way.

If you want Claude to remember preferences across sessions (e.g. "always format emails this way"), ask it to "save that as a memory" and it'll create a file it auto-loads next time.

What if it gets something wrong or makes something up?

It happens. Claude is a strong drafter, not a source of truth. Treat output the way you'd treat a smart intern's first draft: skim it, fix the parts that don't match reality, ship the rest. Anything that's going to a customer should pass your eyes before it goes anywhere.

If you catch a hallucination, just tell it. "That's wrong — the renewal date is March, not May." It'll correct.

4 Working with AI — how to actually be good at this

Six things that separate "AI saved me hours this week" from "AI got me in trouble." Read these once before you start — they'll save you a lot of cleanup.

Tell it what you want like you'd brief a teammate. "Write me an update" is too vague. "Write me a weekly update for these 5 accounts, 3–4 bullets each, focused on what changed this week and what's at risk" gets you something useful. Specific in, specific out.

It can only see what you give it. Claude does not read your inbox, your Slack, or your calendar on its own. If you want it to summarize this week's customer emails, you have to put those emails in the folder first. Section 5 walks you through exactly how.

Always read every line before you send. Especially the first dozen times you use it. Treat the output like a draft from a smart, fast intern: usually right, occasionally confidently wrong. If it invents a date, an exec name, or a commitment, you're the one who sent it. Audit anything going to a customer or to leadership.

Iterate. Don't expect one-shot magic. The first draft is a starting point, not the answer. Tell it specifically what's off: "tighten the second bullet," "the VP didn't say that, he said this," "less corporate." Each correction makes the next draft sharper. Three or four rounds is normal.

Show it what good looks like. If you have a previous deliverable you were happy with — an old email, an old update, a previous brief — drop it in the folder and tell Claude to match the style. This is the single biggest quality lever you have.

More context, better output. Bad: "write a renewal email." Good: "write a renewal email to the VP of Eng at the customer. Renewal is in 60 days. Last call they were worried about the integration timeline. Tone: warm but direct. Under 150 words." The second prompt isn't longer for the sake of it — every detail changes what comes back.

5 Slash commands and power tricks

While you're typing a message to Claude, type a forward slash (/) at the start of the line. A menu of commands pops up. These are shortcuts — small, named workflows you can fire off without writing a long prompt. Some are built in. Some you can build yourself. Below are the ones worth knowing.

Built-in slash commands

CommandWhat it doesWhen to use it
/help Lists every slash command available right now. When you forget what's possible.
/clear Wipes Claude's memory of this conversation and starts fresh. Between unrelated tasks. Stops earlier context from polluting the new task.
/init Creates a CLAUDE.md file that teaches Claude about this folder — what it is, how you work, what to keep in mind. Once per folder you'll use a lot. Worth doing for your weekly-updates folder.
/support Diagnoses common Claude Code install/sign-in issues. Routes you to #claude-code-support if it can't fix it. When something isn't working.
/exit Quits Claude. End of session.

Things you can do that look like magic

Make your own slash command (a "skill")

You can teach Claude a custom command that does exactly what you want, every time. For example, /weekly-update could run the whole flow from Section 6 with one keystroke.

The way you make one is genuinely the easiest part: just ask Claude to make it for you. In any Claude session, type:

I want to create a slash command called /weekly-update that
[describe what you want it to do]. Set it up for me.

Claude will create the files and put them where they need to go. Next time you launch Claude, type /weekly-update and it runs.

Good candidates for custom commands:

  • /qbr-prep — pulls your QBR template prompt with your standard structure baked in
  • /audit-this — runs a customer-facing draft through your usual checks before you send
  • /call-summary — your house style for turning raw notes into a clean recap
Ask Claude to interview you

Genuinely the most underused trick. When you have a vague idea but don't know how to brief it, flip the script:

Interview me. I want to write a [renewal email / QBR brief /
weekly update / whatever]. Ask me one question at a time
until you have enough to draft something I'd actually send.
Don't ask everything at once — go one at a time and react
to my answers.

Claude asks you a question. You answer in plain English. It asks the next one. After 5–8 questions it has more context than you'd ever bother typing into a prompt — and the draft that comes out is dramatically better.

Ask it to challenge your thinking before you ship

Before you send something high-stakes, paste your draft and say:

Be a skeptic. Read this like you're the customer's procurement
team / the VP I'm sending it to / a competitor's AE. Where would
you push back? What's vague, hedgy, or making promises I can't
keep? Don't be polite — be useful.

It's not that Claude is smarter than you. It's that you've been staring at the draft for 20 minutes and can't see it fresh anymore.

Save context across sessions with a CLAUDE.md file

Run /init once in a folder. It creates a file called CLAUDE.md that Claude auto-reads every time you launch in that folder.

Edit that file (it's just text) to include things like:

  • "My accounts are: [list your accounts]."
  • "I'm a CSM in Health & Life Sciences. Don't suggest revenue plays — that's the AE's job."
  • "Tone preference: direct, no corporate fluff. Under 150 words for emails unless I say otherwise."

From then on, Claude already knows that going in. You don't have to repeat it every time.

Drag a file (or screenshot) directly into the conversation

Working in Terminal: drag a file from Finder into the Terminal window. The file path drops in as text. Claude can then read it.

Working in the desktop app: same thing, drag right into the chat box. For screenshots, Cmd+Shift+4 to capture, then drag it in. Claude can read screenshots too — useful for "what does this dashboard tell us" or "this error keeps showing up, what is it?"

Ask "what should I have asked?"

After Claude finishes a task, before you accept the answer, try this:

What should I have asked you that I didn't? What's missing
from this output that I might not realize is missing?

It's a quiet way to catch the gap you didn't know you had.

Two prompts to keep in your back pocket (these change everything)

Two phrases worth using almost every session. Borrowed from Matthew Ricci's setup:

Ask me clarifying questions if it will help improve the output.

Drop this into almost any prompt. Claude will pause and interview you instead of guessing — and the output gets visibly better.

Let's start with a plan and refine it before acting.

For anything multi-step. Claude proposes a plan, you correct it, then it executes. Saves you from "well, that's not what I wanted" moments.

The inbox / outbox trick

Inside any folder you work in regularly, make two subfolders: inbox and outbox.

  • Inbox — drop files here for Claude to read (call notes, PDFs, exported emails).
  • Outbox — tell Claude to leave finished drafts here.

Sounds tiny. Once you've used it a week, you stop losing track of which version is which. (Credit: Matthew Ricci.)

Talk to Claude instead of typing — Wispr Flow

Wispr Flow is a Mac dictation tool that turns your voice into clean text in any app, including Claude. The reason it matters: when you're talking, you give more context naturally — the kind of detail that makes prompts good. Most people type two sentences. With voice, they ramble five, and the output gets dramatically better.

6 A worked example: your weekly account update

This walks through one full task end to end — a weekly account update sent in Slack — so you can see how the pieces fit together. The same flow works for almost any "draft something based on what happened this week" task.

Set this up once (5 minutes, then never again)

You're making a home for these updates. One main folder, then a sub-folder for each week.

  1. Open Finder. Go to Documents.
  2. Right-click in the empty space and choose New Folder. Name it Weekly Updates.
  3. Open TextEdit (Cmd+Space, type "TextEdit," hit Enter).
  4. Paste in one of your previous weekly updates that you liked. The most recent good one is fine.
  5. In TextEdit, click Format → Make Plain Text (so it saves cleanly with no hidden formatting).
  6. Click File → Save. Navigate to the Weekly Updates folder you just made. Name the file style-example.txt. Save.

That style-example.txt file is the most important thing in this whole setup. It teaches Claude what your voice sounds like. The closer the example matches the format and tone you actually want, the less editing you'll do every week.

Tip: if you have two or three previous updates you liked, paste them all in (separated by a row of dashes). Claude picks up patterns better from a few examples than from one.
Step 1 — Make a folder for this week

Inside Weekly Updates, right-click → New Folder. Name it with this week's date in YYYY-MM-DD format, like 2026-06-09. Year-first so they sort in order on screen.

Then drag a copy of style-example.txt from the parent folder into this week's folder. (Hold Option while dragging to copy instead of move.) That way every week's folder has the style example sitting right next to the source material.

Step 2 — Drop this week's source material into the folder

Pick whichever of these you have. You don't need all of them. The more you give Claude, the sharper the draft.

From Slack: open Slack and find the customer threads from this week. Highlight the messages, Cmd+C to copy. Open TextEdit, paste, save into your week folder as something like slack-northwell.txt. Repeat per customer.

From email (Outlook on Mac): open Outlook. Find a customer email thread from this week. Drag the message directly out of the Outlook email list and drop it into your week folder in Finder. It saves as a .eml file that Claude can read. Repeat for each thread you want included.

If drag-and-drop doesn't work cleanly: select the message body, copy, paste into TextEdit, save as plain text into the week folder. Same result.

From call notes: drop them in. PDF, Word, plain text — Claude reads all of those.

From your head: often the most useful thing. Open TextEdit, type out what happened in plain language. Don't worry about writing well, just write it down. Like this:

Customer A — Tuesday call with VP of Eng. Security review delayed
again, their internal team is the blocker. Follow-up Friday.

Customer B — quiet week, no movement. Renewal still on track
for August.

Customer C — escalation Thursday, integration broke after their
patch deployment. We have a fix going Friday.

Save it as my-notes.txt in the week folder. Claude turns notes like this into clean prose.

Rule of thumb: five lines of "this week was busy" gives you a vague update. Five paragraphs of who-said-what gives you a sharp one. The output is only as good as what you put in.
Step 3 — Launch Claude in that folder

Right-click your week folder (the dated one) in Finder. Choose Services → New Terminal at Folder. A Terminal window opens, already inside that folder. Type:

claude

Hit Enter. You're in.

Step 4 — Ask for the first draft

Copy this in. Edit the bracketed parts to match your accounts:

I send a weekly account update in Slack. Here's how I want it:
- One section per account
- 3-4 bullets per account
- Each bullet covers: what changed, what the risk is, what's next
- Tone: direct, no corporate fluff, no hedging
- Whole thing under 400 words

The accounts I cover are: [list your accounts here]

In this folder you'll find this week's source material —
emails, Slack exports, call notes, my own brain-dump notes.
There's also a file called style-example.txt that shows the
voice and format I want to match.

Read everything in the folder, then draft this week's update.

Hit Enter. Claude reads the folder, then writes a draft. This usually takes 30-60 seconds.

Step 5 — Audit (this is the part you cannot skip)

Read every line of the draft. Specifically check for:

  • Wrong names — wrong customer, wrong exec, wrong product. It happens.
  • Wrong dates — "renewal is in March" when it's May.
  • Commitments you didn't make — "we promised X by Friday" when you didn't.
  • Plausible-but-not-real details — these are the dangerous ones because they sound right.
  • Tone that's off — too corporate, too casual, too hedgy.
Don't send anything you haven't read line by line — especially in the first month or two of using this. AI confidence and AI accuracy are not the same thing. The output reads like it knows what it's talking about even when it doesn't. You are the last line of defense.
Step 6 — Iterate (this is the part most people quit too early on)

Found something off? Tell Claude exactly what. A real exchange looks like this:

You:  The Customer A section is wrong — the VP didn't say
      integration is delayed, he said the security review
      is delayed. Fix that and tighten the rest of that
      section.

Claude: [revised draft]

You:  Better. Now the Customer B section — bullets 1 and 2 are
      saying the same thing. Merge them.

Claude: [revised again]

You:  Last thing — the closing line is too soft. Make it
      a clear ask, not a check-in.

Keep going until you'd be comfortable putting your name on it. Three or four rounds is normal. If you're still not happy after five, the problem is usually upstream — the source material was thin, or the style example doesn't actually match what you want. Fix that, then ask for a fresh draft.

Step 7 — Format for Slack and send

Once the content is right:

Format this for a Slack message. Use Slack's bold (*asterisks*)
and bullet style. Keep paragraph breaks tight.

Copy the result, paste into Slack, send. Done.

What this looks like once it's a habit

After a few weeks, the whole flow takes 15–25 minutes:

  • ~5 min: drag this week's emails / Slack exports / notes into the week folder
  • ~2 min: launch Claude, paste the prompt
  • ~10 min: read, audit, iterate 2–3 times
  • ~2 min: format for Slack, paste, send

The first time will take longer. That's expected. Most of the investment is in the style example and getting comfortable with the iteration loop — not in any single week's update.

7 More starter prompts

Below are starter prompts. Drop the relevant files into your Claude folder first (call notes, success plans, email exports), launch Claude, and try one.

Summarize a customer call into a structured note

Drop the call recording transcript or your raw notes in the folder, then:

Read the call notes file in this folder. Give me:
1. The 3-5 things the customer actually cared about (their words, not mine)
2. Any commitments I made
3. Open questions I owe them
4. Risks or red flags I should flag internally
Draft a follow-up email after a meeting 
Based on the call notes, draft a follow-up email to [Customer Name].
Tone: warm but direct, no fluff. Keep it under 150 words.
Include: a one-line recap, the commitments I made with dates,
and one specific next step that keeps momentum.
Prep for a QBR or exec briefing 
I have a QBR with [Customer] next week. In this folder are their
success plan, the last 3 call notes, and their renewal date.

Draft a one-page exec brief covering:
- What they came in wanting
- What we've actually delivered
- Where we're behind or at risk
- What to ask for in the meeting (specific, not generic)
Compare two versions of a document 
There are two success plans in this folder — the Q1 version and
the Q2 version. Tell me what changed: new commitments, removed
items, shifted dates, and anything that looks like scope creep.
Pull together a renewal narrative 
Renewal is in 90 days. Look at the call notes, the success plan,
and the usage data CSV. Build me a renewal narrative I can use
internally:
- Value delivered (with specifics, not adjectives)
- Friction we caused or didn't solve
- What expansion looks like if it goes well
- What to watch for if it doesn't
Stress-test your own draft before sending 
Here's an email I'm about to send to [VP at customer]. Read it
like you're the recipient. What would make you push back, ask
a clarifying question, or feel managed? Suggest tighter wording
where I'm being vague.

8 When something breaks

First stop: inside Claude, type /support. It walks you through common install, sign-in, and setup issues, and hands off to #claude-code-support on Slack with a pre-filled diagnostic if it can't fix it.

If Claude won't launch at all: open Terminal and run claude doctor — it prints what's wrong.

If you're stuck and the above doesn't help: drop into #claude-code-support on Slack with a screenshot of what you're seeing.
